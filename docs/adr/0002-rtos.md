# ADR-0002: rtos as template replication 1

Status: accepted
Date: 2026-10-03
Scope: embedded-skills-deep-update v1.0.0, Phase 3

## Context

`mcu` template accepted (ADR-0001). `rtos` is next: scheduling decisions are
safety-relevant in every domain overlay (ISO 26262-6, DO-178C, IEC 61508).

## Decision

Replicate the `mcu` template structure with RTOS-specific content pinned to
Phase 2 research: FreeRTOS 202604 LTS (kernel 11.3.0, MPU support, to
2028-04-30), Zephyr LTS (POSIX subsets, tickless scheduler, 1000+ boards).
Fixed-priority preemptive default, priority inheritance on shared mutexes,
analytical stack sizing with guards, WCET budgets with measured evidence.

## Consequences

- Positive: scheduling rationale becomes auditable evidence, not tribal knowledge.
- Negative: timing evidence requires hardware access for full verification.
- Follow-up: human review mandatory before the `rtos` PR (safety-relevant).
